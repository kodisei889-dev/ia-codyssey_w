# ia-codyssey_w
Github와 Codyssey를 연동하기 위해 만들어진 Repository입니다.

# 실행 방법
1. 교육장에서 (Local 환경)
로컬 파이썬 환경에서 직접 실행하여 출석을 기록합니다.

python attend.py

2. 집에서 (Docker 환경)
도커를 이용해 독립된 환경에서 실행하며, 볼륨 마운트를 통해 데이터를 보존합니다.

이미지 빌드: docker build -t my-attend-app .
컨테이너 실행:
docker run -it -v ${PWD}:/app my-attend-app

# 문제 해결 (Troubleshooting)
문제: 도커 컨테이너 안에서 출석을 기록했는데, 컨테이너를 종료하면 기록이 사라지고 내 컴퓨터(호스트) 폴더의 attendance.txt에도 반영되지 않는 현상 발생.

해결: 도커 실행 시 -v (볼륨 마운트) 옵션을 사용하여 내 컴퓨터의 현재 폴더(${PWD})와 컨테이너 안의 /app 폴더를 연결함. 이를 통해 컨테이너에서의 변경 사항이 호스트 파일 시스템에 즉시 저장되도록 해결함.

# 공부 기록
## 모른 것
도커 컨테이너 내부에서 생성되거나 수정된 파일이 왜 내 컴퓨터(호스트) 폴더에는 나타나지 않는지, 그리고 컨테이너를 끄면 왜 데이터가 사라지는지 몰랐습니다.

## 처음 물은 것
"도커에서 출석 체크를 했는데 왜 attendance.txt 파일에 이름이 추가되지 않나요?"

## 다시 물은 것
컨테이너 안에서는 파일이 써지는 것 같은데, 컨테이너 밖(VS Code)에서는 보이지 않는 이유가 무엇인지, 둘을 연결하는 구체적인 방법이 무엇인지 되물었습니다.

## 확인한 방법과 결과
명령어에 -v ${PWD}:/app 옵션을 추가하여 실행한 뒤, 도커 안에서 이름을 입력했습니다. 그 결과, 컨테이너가 실행 중인 상태에서 내 컴퓨터의 attendance.txt 파일에 실시간으로 이름이 적히는 것을 확인했습니다.

## 내 말로 정리
도커 컨테이너는 기본적으로 자기만의 격리된 방을 가집니다. 그래서 밖(내 컴퓨터)과 소통하려면 -v 옵션으로 '창문(통로)'을 만들어줘야 합니다. 이것을 볼륨 마운트라고 하며, 이를 통해 컨테이너가 사라져도 데이터는 내 컴퓨터에 안전하게 남게 됩니다.

## 브랜치 생성 및 이동
git checkout -b feature-rate  
(이제 main이 아닌 feature-rate라는 별도의 작업 공간에서 작업하게 됩니다.)  

## 커밋 및 합치기(Merge)
git add .  
git commit -m "출석률 계산 기능 추가"  
git checkout main        # 메인으로 돌아가기  
git merge feature-rate   # 만든 기능 합치기  
  

## 기억할 것 [저장]  
git add . # 모든 변경 사항을 스테이징 영역에 추가  
git add 파일이름.확장자  
git commit -m "코멘트"  
git push origin main  

항상 add - commit - push 단계로 해야 한다.  
git add: 세이브 포인트를 찾아서 앞에 서 있는 상태 (준비)
git commit: [저장하시겠습니까? -> YES] 를 눌러서 슬롯 1번에 저장 완료! (확정)  
git push: 내 컴퓨터에 저장된 슬롯 1번 데이터를 클라우드 서버에 백업하기 (전송)  

# 출석 관리 시스템 고도화 (심화 학습)  
  
1. 기능 분리 및 설정 파일 도입 
   
[문제 상황]  
기존에는 프로그램 코드 안에 날짜를 직접 적어야 해서, 매달 날짜가 바뀔 때마다 코드를 수정해야 하는 번거로움이 있었습니다. 또한, 출석을 기록하는 기능과 조회하는 기능이 섞여 있어 관리가 어려웠습니다.

[해결 방법]  
기능 분리: 출석을 기록하는 attend_branch.py와 결과를 조회하는 query_attendance.py로 역할을 나누었습니다.
설정 파일(config.txt): 조회 기간(시작일, 종료일)과 기준 수업 일수를 json 형식으로 저장하여, 코드 수정 없이 설정값만 읽어와서 동작하도록 개선했습니다.  

2. 사용자 경험(UX) 개선: 예외 처리  
  
[질문]  
"현황 조회 시 기간 설정을 안 해두었으면, 에러가 나는 대신 설정을 먼저 하라고 안내할 수 없을까요?"  
  
[해결]  
프로그램 시작 부분에 os.path.exists()를 사용하여 config.txt 파일이 있는지 확인하는 로직을 추가했습니다. 파일이 없으면 친절한 안내 메시지와 함께 sys.exit()로 프로그램을 안전하게 종료하도록 처리했습니다.  
  
3. 비즈니스 로직 심화: 요일별 필터링  
  
[질문]  
"수업 일수를 직접 입력하는 대신, 평일/주말 여부에 따라 자동으로 계산하고 싶어요. 만약 평일 수업인데 주말에 출석했다면 그 기록은 어떻게 처리하죠?"  
  
[해결]  
자동 수업 일수 계산: datetime 모듈의 weekday()를 활용하여 특정 기간 내의 평일(월-금) 혹은 선택한 요일의 개수를 자동으로 계산합니다.  
데이터 필터링 및 분리:  
정식 출석: 설정된 요일에 출석한 기록만 출석률 계산에 포함합니다.  
수업 외 출석: 수업이 없는 날(예: 주말)에 기록된 데이터는 하단에 [주의] 항목으로 따로 표시하여 사용자에게 알립니다. 

4. 내 말로 정리  
  
프로그램이 단순히 데이터를 저장하는 것을 넘어, **'사용자가 실수할 수 있는 상황'**을 미리 대비하는 법을 배웠습니다.  
설정 파일이 없으면 안내를 해주고, 수업이 없는 날 찍힌 도장은 따로 분류해 주는 로직을 통해 실제 서비스에서 발생할 수 있는 예외 상황을 처리하는 능력을 키웠습니다.  
특히 datetime 라이브러리를 활용해 복잡한 날짜 계산을 자동화하면서, 컴퓨터에게 규칙을 맡기고 사람은 결과만 확인하는 효율적인 구조를 이해하게 되었습니다.
